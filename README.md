# Avito OCR Text Orientation

Решение задачи на определение ориентации текста в OCR кропах
Нужно предсказать `p_180`, то есть вероятность того, что текст на изображении повернут на 180 градусов
Основная метрика задачи: `1 - Brier Score`

## Данные

В задании нет обучающей выборки, поэтому для обучения я использовал два внешних OCR датасета

1. MJSynth  
https://huggingface.co/datasets/priyank-m/MJSynth_text_recognition
2. Bilingual OCR RU/EN Synthetic  
https://huggingface.co/datasets/tehnik-tehnolog/bilingual-ocr-ru-en-synthetic
Из каждого исходного изображения делаются два примера.
`label = 0` для исходной ориентации.
`label = 1` для изображения, повернутого на 180 градусов
Train и validation делятся до создания этих пар, чтобы одно исходное изображение не попадало сразу в обе выборки

## Предобработка

Все изображения приводятся к размеру `48 x 384` с сохранением пропорций. Свободное место заполняется padding
Так как внешние датасеты синтетические, а тестовые OCR кропы могут быть намного хуже по качеству, во время обучения используются аугментации
Используются blur, изменение яркости и контраста, небольшие перспективные и геометрические искажения, а также случайный grayscale
После этого изображения нормализуются значениями ImageNet, которые используются pretrained весами MobileNetV3-Small

## Модель

В качестве модели используется pretrained `MobileNetV3-Small` из torchvision
Последний слой классификатора заменен на один выходной logit
Для обучения используется `BCEWithLogitsLoss` и Adam
Сначала я отдельно обучил модели на MJSynth и bilingual датасете и проверил, как они работают на данных друг друга
После этого итоговая модель обучалась на смеси двух датасетов
Финальная mixed модель обучается 8 эпох. Лучшие веса выбираются по метрике `1 - Brier Score` на validation
MobileNetV3-Small выбрана потому, что для этой задачи важна не только точность, но и скорость инференса

## TTA

При предсказании используется Test Time Augmentation
Модель делает предсказание для исходного изображения и для этого же изображения после поворота на 180 градусов
Так как после поворота класс должен поменяться, итоговая вероятность считается так:

```python
p_180 = (p_original + (1 - p_rotated)) / 2
```
